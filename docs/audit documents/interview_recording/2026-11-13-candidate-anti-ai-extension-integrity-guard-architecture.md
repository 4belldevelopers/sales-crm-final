## 1. Executive Summary & Problem Landscape

With the widespread rise of AI interview assistants (ChatGPT, Claude, Copilot, Interview Coder, Final Round AI, Ecoute, and custom Chrome extensions), recruiters face a severe trust crisis:
- **Real-Time Speech-to-Text & Prompting:** Candidates use browser extensions or floating windows that listen to the interviewer's voice and generate prompt answers on the fly.
- **Off-Screen Reading:** Candidates read answers from secondary monitors, iPads, or tiled browser windows.
- **Code Pasting:** Solutions to coding challenges are generated by AI and pasted into the editor in a single click.

Because JERO hosts the interview natively at `jero.works/interview/{token}`, JERO has **direct access to the candidate's browser DOM, device APIs, and video stream**. This document details the **JERO AI-Guard & Extension Telemetry Engine**, running **100% Client-Side** with **0% server strain**, delivering real-time recruiter alerts and post-interview integrity scoring.

## 3. The 5 Client-Side Integrity Vectors (Zero Server Compute)

### Vector 1: Window Focus & Tab Blur Telemetry (`visibilitychange` & `blur`)
When a candidate switches tabs or clicks outside the interview window to access ChatGPT or a search engine:
- `document.addEventListener('visibilitychange')` fires if the tab is hidden.
- `window.addEventListener('blur')` fires immediately if the candidate clicks into a tiled window or desktop overlay.
- **Engine Logic:**
  ```javascript
  let blurStartTime = null;
  window.addEventListener('blur', () => {
      blurStartTime = Date.now();
      window.jeroGuard.emitTelemetry('WINDOW_UNFOCUSED', { timestamp: blurStartTime });
  });
  window.addEventListener('focus', () => {
      if (blurStartTime) {
          const duration = Math.round((Date.now() - blurStartTime) / 1000);
          window.jeroGuard.emitTelemetry('WINDOW_REFOCUSED', { durationSeconds: duration });
          blurStartTime = null;
      }
  });
  ```
- **Recruiter Alert:** If unfocused for $> 3$ seconds, the recruiter sees a live pill: `⚠️ Candidate switched away from interview (4s)`.

---

### Vector 2: Chrome Extension & Shadow DOM Injection Probing
AI interview extensions typically inject DOM nodes, custom CSS stylesheets, transparent overlay iframes, or floating tooltips into the webpage to show AI responses:
1. **DOM Mutation Observer:**
   ```javascript
   const observer = new MutationObserver((mutations) => {
       for (const mutation of mutations) {
           for (const node of mutation.addedNodes) {
               if (node.nodeType === 1) { // ELEMENT_NODE
                   // Check for suspicious injected iframes, shadow roots, or non-JERO elements
                   if (node.tagName === 'IFRAME' && !node.dataset.jeroAllowed) {
                       window.jeroGuard.flagViolation('SUSPICIOUS_DOM_INJECTION', { tag: node.tagName, id: node.id, class: node.className });
                   }
               }
           }
       }
   });
   observer.observe(document.documentElement, { childList: true, subtree: true });
   ```
2. **Global Namespace & Web-Accessible Resource Probing:**
   - Detects extensions that modify `window.navigator` or inject global properties commonly associated with automated tools.

---

### Vector 3: Clipboard & Keystroke Dynamics (Anti-Copy/Paste & Velocity)
1. **Clipboard Interception:**
   - If the interview includes a technical assessment or question prompt:
   - `copy` and `paste` events on prompt questions are intercepted and logged.
   - If candidate tries to copy the question text to feed it into an AI prompt:
     `e.preventDefault()` can be enabled, or an alert logged: `⚠️ Question copied to clipboard`.
2. **Burst Keystroke Velocity (AI Code Insertion Detection):**
   - Human developers type code at **40–90 words per minute**, with pauses, cursor movements, and backspaces.
   - If an entire 40-line solution appears in $< 500$ milliseconds, it is an instant mathematical certainty that code was pasted or injected from an AI assistant.
   - The engine logs: `🚨 38 lines of code inserted in 120ms (Pasted/AI Generated)`.

---

### Vector 4: Client-Side Gaze Tracking (MediaPipe WebAssembly in Browser RAM)
- Using Google's open-source **MediaPipe Face Landmarker** running **100% client-side in browser WebAssembly** (0% server load):
- Tracks eye iris coordinates and head yaw/pitch angles from the candidate's existing webcam stream:
  - **Normal behavior:** Candidate looks at the camera or the center screen.
  - **AI Reading pattern:** Candidate eyes consistently look off-screen (bottom-left or to a second monitor) reading long horizontal lines for 20+ seconds while verbally answering.
- Flags: `⚠️ Off-screen reading detected (Duration: 18s)`.

---

### Vector 5: Mandatory Display Surface Verification (Full Screen Sharing)
When screen sharing is required during technical interviews:
- Browser API `getDisplayMedia` exposes `track.getSettings().displaySurface`:
  - `displaySurface === 'monitor'` $\rightarrow$ Candidate is sharing their **entire physical screen**.
  - `displaySurface === 'window'` or `'browser'` $\rightarrow$ Candidate is only sharing one window/tab (allowing them to hide ChatGPT on the other half of the screen).
- JERO enforces: *"To ensure integrity, please share your Entire Screen."* If the candidate selects a single window, the room prompts them to re-share the full display.

## 5. Summary of Zero Server Strain & Economics

- **Zero Cloud GPU / Zero Python AI APIs:** The Gaze Tracking runs via **MediaPipe WebAssembly** inside the candidate's own browser using their local GPU/CPU.
- **Zero JERO Server Overhead:** Telemetry updates are small 200-byte JSON messages transmitted over the existing **Laravel Reverb WebSocket channel**.
- **Monetization Power:** This can be packaged as **"AI-Guard & Proctoring Intelligence"** in Enterprise subscription tiers, giving JERO a massive competitive advantage over Google Meet and Zoom.
