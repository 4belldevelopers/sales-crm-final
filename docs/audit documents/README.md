# 📑 Central Audit Documents & Review Archive

> **Mandatory AI & Engineering Storage Location**:
> All new documentation for **Audits**, **Feedback**, **Code/System Changes**, **New Features/Proposals**, and **Optimization Suggestions** MUST ALWAYS be saved in this folder (`docs/audit documents/`).
> This ensures that whenever we need to review, track, or verify historical recommendations and implementations, they are organized and persistently accessible in one standard location.

---

## 📂 Document Types Covered

1. **Audits (`*-audit.md`)**:
   - Forensic architecture, UI/UX, CQRS read compliance, 10K concurrency, and security audits.
2. **Feedback (`*-feedback.md`)**:
   - Recruiter, product owner, stakeholder feedback reports and review notes.
3. **Changes / Refactors (`*-changes.md` or `*-refactor.md`)**:
   - Technical breakdown of changes made, migration notes, and backward-compatibility validations.
4. **New Features (`*-feature.md` or `*-proposal.md`)**:
   - Feature specifications, data dictionaries, DTO mappings, and implementation blueprints.
5. **Suggestions / Optimizations (`*-suggestions.md`)**:
   - Proposed performance optimizations, UI/UX improvements, and architectural suggestions.

---

## 🏷️ Naming Convention

All new documents must follow this standardized naming pattern:
`YYYY-MM-DD-<module-or-topic>-<document-type>.md`

### Examples:
- `2026-11-03-candidate-drawer-audit.md`
- `2026-11-03-modern-card-subcard-feedback.md`
- `2026-11-03-commercials-engine-phase8-changes.md`
- `2026-11-03-bench-marketplace-new-feature.md`
- `2026-11-03-elasticsearch-read-optimization-suggestions.md`
