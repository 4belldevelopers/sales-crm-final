## TL;DR & System Profile
- **Product:** JERO — multi-tenant B2B hiring SaaS = GOD-level ATS + talent marketplace (companies trade talent).
- **Architecture:** CQRS: **MySQL strictly for writes (`INSERT`/`UPDATE`/`DELETE`)**, **Elasticsearch strictly for reads (100% search/queries/filters)**, Redis/Horizon queues, Octane/FrankenPHP, Reverb.
- **Hardware Profile:** Dedicated **32 GB RAM each** for Web/App Server, MySQL database, and Elasticsearch cluster.
- **Scale Target:** **10,000 concurrent users per page** with **0% server/DB read strain** achieved via Client-First / Browser-Execution (User RAM + WASM) with server fallback.
- **Work folder:** `testing.jero.works` (this one). Never `hire.jero.works`.
- **Read order:** [CLAUDE.md](CLAUDE.md) → [docs/AI_BOOTSTRAP.md](docs/AI_BOOTSTRAP.md) → [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) → [docs/AI_RULES.md](docs/AI_RULES.md) → [docs/GLOSSARY.md](docs/GLOSSARY.md) → [docs/Latest_Technology_JERO.WORKS/LATEST_TECHNOLOGY_FOR_JERO_WORKS.md](docs/Latest_Technology_JERO.WORKS/LATEST_TECHNOLOGY_FOR_JERO_WORKS.md).

## Non-negotiable Rules (Full list: [docs/AI_RULES.md](docs/AI_RULES.md))
1. **MySQL is ONLY for Add / Edit / Delete:** 0% MySQL reads on web/API request paths. No `SELECT` or joins on user page loads.
2. **Elasticsearch is ONLY for Read (Universal Scope):** Serves 100% of queries, filters, counts, and search results across ALL data domains (candidates, jobs, requisitions, applications, companies, coins, teams) across all 60+ indices. Zero direct UI writes.
3. **Client-First Execution (User RAM & Browser CPU First):** Heavy assembly (PDFs, WASM, formatting, previews) executes in user RAM. Server/ES is strictly a circuit-breaker fallback.
4. **10K Concurrency / 0% Server Strain Target:** Architect every page to handle 10,000 concurrent users without server collapse or UI freezes.
5. **Zero Stale Data in ATS:** Recruitment pipeline data must be 100% fresh, correct, and authoritative. Latency optimization must never serve stale candidate data.
6. **Multi-Tenant Atomic Cache Invalidation:** When candidate/job/stage details are updated, tenant cache keys (`company_id`) in Redis and client memory are instantly destroyed so all organization users see updated data in real time.
7. **Zero Business Logic Mutations & Zero Module Regressions:** For any change or upgrade on any page/feature, existing core business logic must remain 100% untouched, and NO other feature, drawer, modal, or module across the system may be affected.
8. Database truth = `database/schema/mysql-schema.sql` (217 tables) — read it before any DB work. Not in migrations; don't invent migrations.
9. Eloquent is tenant-scoped by `company_id`; raw `DB::table()` is not — filter it.
10. Keep MySQL ↔ Elasticsearch in sync on writes to indexed entities.
11. Use `config()`, never `env()` outside `config/`.
12. Queue heavy work; match existing patterns; no unprompted refactors or business-logic changes.
13. Preserve baked-in name typos (they map to real tables/indices) — rename only via NAMING_CONVENTIONS.
14. UI = Metronic, Poppins font, enterprise typography scale, clean icon-based design (NO 3D). **Must perfectly fit 15.6-inch screens (1366×768 & 1920×1080) and smaller screens** with complete responsiveness and internal scrolling ([docs/UI_UX_STANDARDS.md](docs/UI_UX_STANDARDS.md)).
15. OpenDoc WASM Engine Isolation: Download Resume Center, Forward Resume, and Online Editor are strictly 3 separate engines. Never merge them.
16. **Document the purpose of every new code** — intent comment/docblock on each new file/class/method; intent + tenancy note on complex/raw queries. See [docs/CODE_DOCUMENTATION_STANDARD.md](docs/CODE_DOCUMENTATION_STANDARD.md).
17. **Complete Page/Blade Isolation:** Every page/blade designed, developed, or updated must be completely isolated to that page. Do NOT reuse or share stateful JS/drawers/scripts across pages; changes to one page must never touch or affect another page.
18. **Product Company & Staffing Company Code Freeze:** Files under `resources/views/product_company/` and `resources/views/staffing_company/` (and their respective controllers/modules) are strictly frozen. Do NOT edit or modify them unless explicitly requested. Currency and UI enhancements are strictly scoped to **Service Company** and **Admin**.
19. **Adopt Latest Technologies & Consult Tech Standard:** When implementing or upgrading any new feature, always reference [docs/Latest_Technology_JERO.WORKS](docs/Latest_Technology_JERO.WORKS/LATEST_TECHNOLOGY_FOR_JERO_WORKS.md). Leverage **Bun** for high-speed offline/static compilation & testing, **Mojo / ONNX CPU** for local vector operations (zero cloud AI APIs/LangChain), and **Dragonfly** for 4M QPS multi-tenant caching.
20. **Mandatory Card + Sub-Card Design Standard & Header Background Standard:** All future and refactored entity listings, drawer tabs (such as the Client Drawer Jobs tab), drawers (e.g. Job Status drawer), overview views, and dashboards across JERO **MUST AND ONLY** use the **Modern Card + Sub-Card Enterprise Design System** ([docs/UI_UX_CARD_SUB_CARD_DESIGN_STANDARD.md](docs/UI_UX_CARD_SUB_CARD_DESIGN_STANDARD.md)). Mandatory 3-tier layout: Tier 1 toolbar card with dedicated background color (`#f8fafc`, border `#e2e8f0`, radius 10px) with dynamic right-corner search bar (300ms debounce + clear button) and primary action button; Tier 2 dedicated sub-tabs card (`#ffffff` or soft `#f8fafc`, border `#e2e8f0`, radius 10px) with single active primary blue highlight (`#009ef7`); Tier 3 primary card stream with discrete upper sub-cards (company logo, comp/location, team, agency, pipeline) and bottom activity strip. **MANDATORY HEADER BACKGROUND COLOR:** All drawer headers (`.sd-topbar`, modal headers), card headers (`.card-header`, `.jsd-card-header`), sub-card section headers, and table/matrix header rows (`thead tr`) **MUST ALWAYS** have a dedicated background color (e.g. `#f8fafc` or `#f1f5f9` with crisp border `#e2e8f0`, or soft semantic tint) — never transparent, plain white, or unanchored text. This provides immediate visual hierarchy, establishes distinct section boundaries, and ensures the best enterprise UI/UX implementations. Sprawling raw HTML tables, unstyled floating sub-tabs, and placeholder matching badges ("15 Matching") are strictly forbidden. Must perfectly fit 15.6" screens (`1366×768` & `1920×1080`) with zero horizontal overflow.
21. **Mandatory Storage Location & Module Folder Pattern for Audits, Feedback, Changes, Features & Suggestions:** Any new document created for audits, feedback, modifications/changelogs, new features, or architectural/technical suggestions **MUST ALWAYS** be saved in its dedicated module or feature named subfolder under `docs/audit documents/<module_or_feature_name>/` (e.g. `docs/audit documents/<module_or_feature_name>/YYYY-MM-DD-<topic>-<type>.md`). Saving loose files directly in `docs/` or `docs/audit documents/` root is strictly forbidden. Documents must strictly follow the standard layout (Metadata, Executive Summary, Architecture & Data Flow, File Changes Matrix, 15.6" Screen Fit, Verification Evidence) so anyone can readily understand the changes.
22. **Zero-Cron & Just-In-Time (JIT) Evaluation Standard (Zero Idle Server/Bandwidth Strain):** Never introduce background polling cron jobs, periodic `schedule:run` commands, or recurring database sweepers for record expiration, status timeouts, or state reconciliation unless explicitly authorized. Polling cron jobs consume server CPU/RAM cycles, boot framework overhead repeatedly, and waste database IOPS. Instead, ALWAYS implement **Just-In-Time (JIT) / Lazy Evaluation**: (a) compute expiration/state on read queries (`WHERE expires_at > NOW()`), (b) lazily transition/self-heal expired states on write/access actions within the incoming request transaction, or (c) use delayed queue jobs (`->delay(...)`) for exact one-time events. Zero idle background CPU strain and 0 KB bandwidth waste.
23. **Client-First Resume Parser Engine Parity (`JeroIdentityEngine`):** All resume parsing and ATS field extraction MUST run 100% in client browser RAM (`User RAM + WebAssembly + Client NLP`) with 0% server/DB read strain (ADR 0008). Never introduce backend server parsing endpoints. Name resolution uses 5-vector identity triangulation (spatial decay + bounded email decomposition + strict zero-authority filename tie-breaker capped at +35 pts + negative blacklist + 250+ role truncator). Current company uses the Employment Chronology Resolver (month/year precision, ongoing active roles prioritized, project descriptions ignored), Contextual Academic Guards, and the Canonical Employer Knowledge Graph (`ServiceNow`, `PwC`, `EY`, `HCLTech`, `HP`, `CRED`) with a 3-tier confidence threshold gate ($\ge 140$ High, $80\text{--}139$ Medium, $< 80$ Low/Unconfirmed). Maintain identical parity across all 4 parser bridge files. See [docs/audit documents/resume_parser/2026-11-10-supergod-mode-resume-parser-name-and-company-extraction-architecture.md](docs/audit%20documents/resume_parser/2026-11-10-supergod-mode-resume-parser-name-and-company-extraction-architecture.md).
24. **Mandatory Default User/Account-Setting Timezone with Date & Time:** Whenever displaying any date/time (Posted Date, Sent Date, Request Expiry, Timelines, Drawers, Tables, Exports), ALWAYS resolve the user/organization's configured default timezone from Account Settings (`companies.timezone` via `GeneralMethod::defaultTimeZone($company_id)` on the backend or `GeneralMethod::getTenantDefaultsPayload($company_id)` on the client — never raw un-converted DB/ES timestamps or hardcoded timezones), convert the timestamp into that timezone, and always display **date, time, and timezone abbreviation together** (e.g., `12 Nov 26, 03:45 PM IST` via `d M y, h:i A T`).
25. **Canonical Job Classification Tags & Color Combinations (Zero Ambiguous "Internal" Naming):** NEVER use the bare/ambiguous label `"Internal"`, `"Internal Job"`, or `"Internal Team"` anywhere in visible UI tags, buttons, or headers. Always use exact, unambiguous classification pills and matching color tokens:
    - **Hiring for Own Company (`self_company === true` / internal hiring):** Tag **`My Organization`** (`fa-id-badge`, `.type-my-org`: Cyan `#ecfeff` bg / `#0891b2` text / `#a5f3fc` border; active KPI `data-kpi="my_organization"`: `#ecfeff` bg / `#22d3ee` border / `#0891b2` accent / `#155e75` num). NEVER label own-company hiring as `"Internal"` or `"Internal Client"`.
    - **Managed Non-Marketplace Client (`is_direct_client === false && is_self_company === false`):** Tag **`Internal Client`** (`fa-building`, `.type-internal`: Blue `#eff6ff` bg / `#2563eb` text / `#bfdbfe` border; active KPI `data-kpi="internal"`: Amber/Orange `#fff7ed` bg / `#fb923c` border / `#ea580c` accent / `#9a3412` num). NEVER shorten `"Internal Client"` to `"Internal"`.
    - **Marketplace Client Mandate (`is_direct_client === true`):** Tag **`Direct Client`** (`fa-shield-alt`, `.type-direct`: Emerald `#ecfdf5` bg / `#059669` text / `#a7f3d0` border; active KPI `data-kpi="direct"`: `#ecfdf5` bg / `#34d399` border / `#059669` accent / `#065f46` num).
    - **Inbound Request (`is_job_request === true`):** Render BOTH **`Direct Client`** (`.type-direct` Emerald) AND **`Job Request`** (`fa-handshake`, `.type-request`: Violet `#f5f3ff` bg / `#7c3aed` text / `#ddd6fe` border; active KPI `data-kpi="job_request"`: `#faf5ff` bg / `#c084fc` border / `#9333ea` accent).
